## 4. Vectorize patterns (verified, two live examples)

### 4a. Research embeddings — `src/backend/ai/agents/ResearchAgent/methods/embed-chunks.ts`
- Model: `env.AI.run("@cf/baai/bge-large-en-v1.5", { text: batch })` → `{ data: number[][] }` (:38-41).
- Batches of 100 chunks (`BATCH_SIZE`, :12).
- Upserts to **`env.RESEARCH_INDEX`** (NOT `VECTOR_INDEX`) (:56).
- Vector id scheme: `` `research-${sessionId}-chunk-${i + batchIdx}` `` (:45).
- Metadata shape: `{ sessionId, chunkIndex, textPreview: <first 200 chars> }` (:48-52).
- Namespace: `` `research:${sessionId}` `` (:27, :47) — Vectorize `namespace` field used
  for per-session isolation.
- Deletion: `env.RESEARCH_INDEX.deleteByIds(ids)` (:80) with the same id scheme.

### 4b. Photo/image multi-modal embeddings — `src/backend/services/image-processor/service.ts`
- `this.vectorIndex = env.PHOTO_INDEX` (:58).
- Builds a 1536-dim vector by generating a BGE text-summary embedding (768-dim) and a
  separate "structure" vector (768-dim), L2-normalizing each independently, then
  concatenating (:640-656) — this is why `PHOTO_INDEX` was provisioned with
  `--dimensions=1536` rather than the bge-large-en-v1.5 preset.
- `upsertEmbeddingVector(imageId, text, embeddings)` → `this.vectorIndex.upsert([{ id: imageId, values: embeddings, metadata: { imageId, text } }])` (:671-683).

**For Phase 2 document embeddings**: plan calls for plain `env.AI.run("@cf/baai/bge-large-en-v1.5")`
text embeddings upserted to `VECTOR_INDEX` (the general-purpose `remodel-embeddings`
index, distinct from both `RESEARCH_INDEX` and `PHOTO_INDEX`) with metadata
`{ kind: "document", documentId }`. Follow the `embed-chunks.ts` batching/id-scheme
style (e.g. `` `document-${documentId}-chunk-${i}` ``) rather than the image-processor's
dual-vector concatenation approach, since documents are plain-text embeddings, not
multi-modal.

## 8. Open flags for the swarm (not fixed by context-manager, decide during build)

1. **`/api/documents` naming collision** — the PlateJS notes router already owns
   `/api/documents` (index.ts:144). Saved-views/public-doc endpoints need a different
   mount point or must extend the existing router carefully without touching the notes
   domain.
2. **`PATCH /:id` collision** — `supporting-documents.ts:733` already implements
   `PATCH /:id` with revision-fork (`createRevision`) semantics unrelated to Phase 2's
   visibility/tags/associations patch. Merge carefully or add a new route.
3. **Auth posture** — the entire existing `supportingDocumentsRouter` is currently
   unauthenticated (no `requireAccessAuth`). Phase 2 write endpoints (PATCH,
   associations, saved-views CRUD) should likely get an explicit auth guard mirroring
   the `/api/bid-portfolios/*` public-prefix-passthrough pattern (index.ts:118-125),
   not inherit the historical blanket-public default.
4. **`@llamaindex/liteparse`** is not yet a dependency — add to `package.json` before
   wiring PDF extraction.
