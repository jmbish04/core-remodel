Product Requirements Document: Hybrid AI Construction Budgeting & Sourcing Platform
1. Executive Summary & Vision
The residential construction and renovation industry operates within a paradigm historically fraught with systemic financial opacity, misaligned incentives, and severe, predictable budget overruns. Homeowners frequently enter complex, multi-million dollar capital projects armed only with rudimentary spreadsheets and static PDF bids, leaving them highly vulnerable to industry-standard estimating tactics that obscure the true final costs of a build. The core vision of this product is to engineer a hybrid deterministic and asynchronous artificial intelligence platform that serves as a fiduciary digital consultant, a rigorous bid reconciler, and an automated procurement sourcing agent for homeowners.
By bridging robust construction finance methodologies—specifically adapting the Construction Specifications Institute (CSI) MasterFormat for residential use 1—with sophisticated Large Language Model (LLM) agentic workflows and modern, highly intuitive web interfaces, this application establishes an impenetrable defense against budget inflation. The architecture is deliberately designed around a concept of "Hybrid Intelligence." The system strictly segregates exact mathematical determinism from qualitative stochastic analysis. Deterministic algorithms enforce rigid 20 percent contingencies, track exact line-item variances, and roll up budgets utilizing fixed-precision arithmetic. Conversely, the LLM agents are deployed exclusively for qualitative tasks: detecting "bait-and-switch" allowance tactics in unstructured text, flagging missing structural scope in architectural plans, and autonomously scouring the web for superior product sourcing and installation warnings.
To achieve enterprise-grade reliability, the backend architecture is strictly built upon the Cloudflare Developer Platform. The infrastructure leverages Cloudflare Workers for edge compute, Durable Objects for stateful chat memory and real-time collaboration, Workflows for orchestrating long-running, multi-step deep research tasks, Queues for resilient background processing of dense PDF documents, and D1 SQLite for highly distributed, edge-adjacent relational data storage. The client interface is a responsive React web application utilizing Shadcn UI components and the assistant-ui library to render seamless, persistent chat interfaces.3
Furthermore, the platform acknowledges the behavioral reality of its user base: homeowners inherently trust and utilize external spreadsheet software for financial management. Rather than forcing users into a closed ecosystem, the application maintains a bi-directional, mathematically rigorous synchronization with Google Sheets.4 To prevent catastrophic data corruption during concurrent edits, the architecture establishes the Cloudflare D1 database as the absolute source of truth, enforcing a strict "Last-Write-Wins with Versioning" model that maintains an unalterable revision log and audit trail of all external spreadsheet states.5 The resulting platform represents a paradigm shift in residential construction management, transforming the homeowner from a passive payer into an armed, data-driven procurement manager.
2. Industry Best Practices & Core Relational Data Model
2.1 Foundation: Construction Budgeting Psychology & Methodology
To architect a system capable of defending a homeowner's capital, the underlying data model must accurately reflect the psychological and financial mechanisms utilized in modern construction contracting. Traditional construction contracts heavily rely on the concept of "allowances." An allowance is fundamentally a budget placeholder for materials—the "known unknowns"—that have not yet been explicitly selected at the time the contract is executed.6 Allowances are distinctly different from "contingencies," which are reserved exclusively for "unknown unknowns," such as discovering dry rot during demolition or encountering unmarked sub-surface utilities.7
While allowances serve a legitimate purpose in allowing construction to commence prior to final design selections, they are frequently weaponized by volume builders and unscrupulous contractors as a "bait-and-switch" mechanism to secure the initial contract. To present an artificially low top-line bid, a contractor will intentionally load the proposal with generic, builder-grade allowances for major finishes, cabinetry, and lighting.8 The psychological trap snaps shut months later when the homeowner visits the design center. A homeowner may discover that their $15,000 "appliance allowance" only covers base-model units, while the luxury suite they actually require costs $60,000.8 Because the structure is already partially built, the homeowner has no leverage and must absorb a $45,000 out-of-pocket overage, while the contractor maintains their profit margin on the base contract.8
To counteract this, the platform brings enterprise-level organization to residential projects by adapting the Construction Specifications Institute (CSI) MasterFormat. MasterFormat is a standardized framework utilized in commercial construction to organize specifications, ensuring that all parties interpret information uniformly and minimizing costly miscommunications.2 MasterFormat currently consists of 50 divisions.1 The platform specifically adapts the Facility Construction Subgroup (Divisions 02-19) for residential application.1 By forcing unstructured contractor bids into this standardized hierarchical schema, the platform can structurally identify missing scope and isolate padded allowances.

3. Feature Specifications (The AI Agents & Deterministic Tools)
Feature 3.1: The Gap Analyzer
User Story: As a homeowner reviewing an initial contractor bid, I want the system to automatically analyze the structural integrity of the proposal and flag missing structural or preparatory components so that I am not ambushed by costly change orders once demolition begins.
Research-Backed Rationale: Change orders are the primary mechanism through which contractors recoup lost margins on artificially low initial bids. These change orders frequently stem from missing preparatory work, differing interpretations of architectural drawings, or conveniently overlooked structural realities.14 A prime example is the interplay between CSI MasterFormat Division 09 (Finishes) and Division 07 (Thermal and Moisture Protection).1 If a contractor submits a bid for a luxury bathroom remodel that heavily details the Division 09 tile and fixtures but entirely omits the Division 07 waterproofing membrane, the homeowner faces an imminent risk of catastrophic water damage and subsequent total loss of the finish materials.10
Furthermore, local ordinances often trigger cascading requirements that contractors omit from initial bids to appear competitive. For instance, in San Francisco, extensive renovations on specific properties trigger the Mandatory Soft Story Retrofit Ordinance.15 This ordinance applies to wood-frame structures built prior to 1978 containing five or more residential units and two or more stories over a weak or "soft" ground floor.15 While a standard foundation bolting retrofit may cost $3,200 to $7,500, a full soft-story retrofit costs between $14,000 and $27,000.16 If a homeowner's architectural plans trigger this ordinance, but the contractor's bid omits the seismic engineering and structural steel (Division 05) line items, the homeowner is facing a guaranteed minimum $14,000 overage before framing even begins.1
Deterministic Rules: The application utilizes strict relational logic to enforce scope completeness. If a Room object contains a Budget_Item mapped to Division 09 (Finishes) with descriptors matching "Tile," "Shower," or "Wet Room," the database trigger must algorithmically verify the existence of a corresponding Division 07 (Waterproofing) line item within the same parent Room. Total budget calculations and variance roll-ups are executed strictly using fixed-precision SQL mathematics; no LLM floating-point calculations are permitted to ensure absolute financial accuracy.
LLM Agent Tasks: The primary AI agent acts as a semantic interpreter. It analyzes the qualitative text of the uploaded architectural notes and the contractor's bid to determine if the scope of work reasonably triggers secondary requirements. For example, if the AI detects phrases such as "load-bearing wall removal" or "open concept transition," it cross-references the bid to ensure Division 05 (Structural Steel) and corresponding structural engineering consultation fees are present.
UI/UX Requirements: The frontend leverages Shadcn Alert components (utilizing the Destructive/Red variant) appended dynamically to the top of the budget DataTable. When a user interacts with a flagged row, a Shadcn HoverCard surfaces, providing a plain-English explanation of the specific CSI MasterFormat gap, referencing the precise missing division and citing potential financial consequences.
Feature 3.2: The Bid Reconciler, Risk Predictor, & Negotiation Consultant
User Story: As a user uploading a dense, multi-page PDF contractor bid, I want the system to parse the unstructured text, extract individual line items, compare them against my predefined architectural budget, and provide tactical negotiation scripts based on identified padding or predatory allowance tactics.
Research-Backed Rationale: The financial dynamic between contractors and homeowners is defined by severe information asymmetry. To win a contract, volume builders routinely utilize "bait-and-switch" allowance tactics.8 They present an attractive initial bid loaded with generic placeholders for major finishes. When the homeowner subsequently visits a design center, they discover that their allocated $15,000 "appliance allowance" is sufficient only for basic, builder-grade units, while the luxury suite (e.g., Sub-Zero and Wolf) they specified during initial consultations costs $60,000.8 Because the structure is already under construction, the homeowner is captured; they must absorb the $45,000 variance directly out of pocket.8 Furthermore, contractors dictate that all labor, installation costs, overhead, and profit must be included in the base Contract Sum, not within the allowance itself.6 Labor costs associated with allowances must be strictly separated to prevent contractors from artificially inflating installation fees later.18
Deterministic Rules: The system algorithmically extracts and sums all explicit "Allowance" financial tags versus "Fixed Cost" tags. It then calculates the percentage of the total bid composed of variable allowances. If allowances constitute greater than 30 percent of the top-line bid, the system deterministic triggers a "High-Risk Contract" alert.
LLM Agent Tasks:
* Reconciliation: The parsing agent consumes the PDF text (ingested asynchronously via Cloudflare Workers and Queues) and maps the unstructured contractor line items to the strict internal Budget_Items table, assigning appropriate CSI MasterFormat division codes.
* Negotiation Tactics: A secondary consultant agent generates a room-by-room negotiation script tailored to the homeowner's stated preferences. For instance: "The contractor allocated $15,000 for kitchen appliances. Based on your profile indicating a requirement for luxury brands, historical data indicates this allowance is deficient by approximately $45,000. Instruct the contractor to convert this line item from a variable allowance to a 'No Allowance' fixed-price specification referencing exact model numbers before executing the contract."
UI/UX Requirements: The interface presents a split-pane layout. The left pane renders the original PDF document utilizing a React PDF viewer with highlighted bounding boxes over extracted text. The right pane renders a Shadcn DataTable displaying the extracted, standardized mappings. A floating assistant-ui modal acts as an always-available Negotiation Consultant, maintaining persistent conversation history via Cloudflare Durable Objects.3
Feature 3.3: Human-in-the-Loop Bid Mapping UI
User Story: As a user, if the AI incorrectly maps a vaguely worded contractor line item (e.g., a generic entry for "Kitchen Stuff - $5000") to the wrong MasterFormat division, I require an intuitive visual interface to manually override and correct the mapping, ensuring my budget remains accurate.
Research-Backed Rationale: Complete autonomous parsing of highly unstructured, idiosyncratic construction data is fundamentally fragile. Contractors frequently use non-standard terminology, group unrelated trades into single line items, or provide bids lacking any clear hierarchy. Relying entirely on LLM extraction without a fallback mechanism guarantees data corruption and user frustration. Therefore, a Human-in-the-Loop (HITL) intervention interface is a mandatory architectural requirement.19
Deterministic Rules: Updating a mapping via the manual UI instantly triggers a cascading database transaction. The system recalculates all parent room subtotals, re-evaluates the variance against the baseline allowance, and updates the global contingency state. The manual override is logged immutably in the Sync_Revision_Log with the mutation_source flagged as 'App_UI'.
LLM Agent Tasks: None directly during the manual override. The UI strictly interacts with the Cloudflare Worker API to update the relational mapping in the D1 SQLite database, bypassing the AI parser.
UI/UX Requirements: The frontend implements a robust drag-and-drop interface utilizing the @dnd-kit/core library. Any extracted line items that fall below a 90% AI confidence threshold are isolated into a vertical "Staging Area" column on the left side of the screen. Users can physically drag these unmapped cards into designated "Room / MasterFormat Category" drop zones located in a grid on the right, providing tactile control over the data ingestion process.
Feature 3.4: Asynchronous Deep Research & Sourcing Agent
User Story: As a user finalizing material selections, I want an autonomous AI agent to scour the web for specific fixtures, aggregate pricing across multiple vendors, synthesize hundreds of user reviews to highlight hidden installation "gotchas," and run these heavy tasks in the background without freezing my application.
Research-Backed Rationale: Material sourcing is exceptionally time-consuming, requiring the aggregation of highly distributed, unstructured data across thousands of disparate e-commerce and wholesale web properties. Executing live web scraping and LLM synthesis requires long-running processes that inherently exceed the standard execution timeout limits of serverless functions. Cloudflare Workflows is explicitly engineered for this exact pattern, allowing multi-step logic to be automatically retried and memoized for durability.20 Furthermore, executing broad web searches consumes significant compute resources; therefore, a human-in-the-loop gate is required before initiating deep research. This gating is achieved utilizing the Cloudflare Workflow waitForEvent() API.13
Deterministic Rules: The system enforces a rule that a Deep Research job cannot be initiated unless the target Budget_Item has a defined mathematical budget ceiling in the database. Workflow instances must continually log their internal state transitions ('Queued', 'Scraping', 'Pending_Approval', 'Completed') to the Deep_Research_Jobs D1 table to enable frontend polling.
LLM Agent Tasks: The orchestration agent utilizes the Model Context Protocol (MCP) to execute external tools.21 It triggers web search algorithms to locate material pricing across diverse vendors. Subsequently, it synthesizes end-user reviews specifically hunting for installation difficulties or warranty voids. For example, the agent might report: "While this specific imported tile is under budget, sentiment analysis of 142 reviews indicates it requires a highly specialized epoxy grout that will increase your Division 09 labor costs by $4 per square foot, ultimately causing a budget overrun."
UI/UX Requirements:
* Research Jobs Dashboard: A dedicated routing view listing all active, pending, and completed Workflows. The interface utilizes Shadcn Progress bars to visually indicate the status of active scraping operations.
* Persistent Notifications: A Shadcn notification badge on the global navigation bar alerts the user to unread research results.
* Approval Gate UI: When a research step requires human intervention, a Shadcn Dialog interrupts the user, asking them to confirm the execution of the deep research task. Clicking 'Approve' fires a specialized webhook that satisfies the Cloudflare Workflow waitForEvent promise, allowing the backend agent to resume execution.13
Feature 3.5: The Overage Mitigator & ROI Optimizer
User Story: As a homeowner approaching my maximum financial limit, I want the system to mathematically project my final cost based on current line-item variances and autonomously suggest high-ROI material downgrades in secondary rooms to preserve my critical 20% contingency fund.
Research-Backed Rationale: The standard 20% construction contingency must be fiercely protected against erosion.11 Any remaining contingency at project completion belongs entirely to the homeowner, not the contractor.11 When variances force the reallocation of funds, homeowners must understand the Return on Investment (ROI) of specific materials to make optimal sacrifices. Historical real estate data indicates that a midrange, cosmetic kitchen remodel—focusing heavily on painting existing cabinetry and updating hardware—yields an exceptional 70% ROI.22 When selecting countertops, Quartz provides an optimal 68% ROI due to its zero-maintenance requirements and UV resistance, outperforming Granite (64% ROI), which requires annual chemical sealing.12 If a project is tracking over budget, the system should leverage this data to suggest downgrading a secondary bathroom's custom tilework to a prefabricated acrylic surround, thereby preserving capital to fund the high-ROI Quartz countertops in the primary kitchen.
Deterministic Rules: The system continuously runs a background calculation: Remaining_Contingency = Total_Contingency_Value - SUM(Positive_Variances_Across_All_Rooms). If the Remaining_Contingency metric drops below 5% of the total project value, the system triggers a critical, un-dismissible alert requiring homeowner acknowledgement.
LLM Agent Tasks: The optimization agent analyzes the current Sourced_Products table, identifies items still in the 'Pending Selection' state, and queries the internal ROI knowledge base. It generates highly localized, qualitative suggestions. For example: "Swap custom cherry cabinetry in the laundry room for painted semi-custom (Essentials line 24) to immediately recover $12,000 with statistically negligible impact on final property resale value."
UI/UX Requirements: The UI features a persistent, sticky header across all views displaying a visual budget thermometer. The thermometer transitions dynamically from Green to Yellow to Red based on the mathematical consumption of the contingency fund. When overages occur, Shadcn Cards surface presenting AI-generated "Trade-off Scenarios," complete with bold 'Accept' or 'Reject' action buttons that automatically execute the suggested budget reallocations across the database.
Feature 3.6: The High/Low Variance Dashboard & Sync
User Story: As a power user, I want my application data seamlessly and continuously synchronized with my personal Google Sheet, maintaining a reliable, chronological history of edits so that I never lose critical financial data due to conflicting updates.
Research-Backed Rationale: Despite the existence of specialized software, a vast majority of homeowners and contractors ultimately revert to trusting spreadsheet software for complex financial tracking. Attempting to force users out of this paradigm causes high churn. However, real-time bi-directional synchronization between a web application and an external spreadsheet is technologically perilous without establishing a rigid single source of truth.25 The Cloudflare D1 database must act as this authoritative ledger. Furthermore, to handle strict Google Sheets API rate limits and network latency efficiently, individual cellular updates must be aggressively batched using the spreadsheets.batchUpdate method.26
Deterministic Rules: Every successful write operation to the D1 database triggers the asynchronous dispatch of a Cloudflare Queue message containing the specific JSON Delta of the change. A consumer Worker processes this queue, batching Deltas on a predefined interval, and executes a single, massive batchUpdate payload to Google Sheets.26
Conversely, inbound webhooks generated by Google Sheets App Scripts must submit the altered range and value alongside a timestamp. The D1 ingestion worker checks the Sync_Revision_Log timestamp. If the incoming Sheet's timestamp is older than D1's last recorded edit for that entity, the inbound edit is unequivocally rejected. D1 then forcefully dispatches an outbound update to overwrite the Sheet, maintaining absolute data integrity (Conflict Resolution: Last-Write-Wins with D1 bias).5
UI/UX Requirements: The application includes a dedicated "Sync History & Audit" tab within the settings panel. This view utilizes a heavily paginated Shadcn DataTable, displaying the chronological Sync_Revision_Log. It highlights the mutation_source and surfaces a highly visible "Force Resync to Sheets" manual override button to allow users to manually push the D1 state outward in the event of an API failure.


  



4. Cloudflare Infrastructure & Worker Architecture
The backend infrastructure completely eschews traditional, centralized monolithic servers in favor of the globally distributed Cloudflare Developer Platform. This architecture specifically leverages Cloudflare's purpose-built primitives to handle stateful AI orchestration, long-running processes, and edge-adjacent relational data storage.27
4.1 Cloudflare Workflows (Long-Running Research)
Cloudflare Workflows provide step-based, durable execution necessary for the Deep Research Agent.20 Because web scraping and LLM synthesis can take several minutes and are inherently prone to transient network failures or external API timeouts, Workflows automatically handle execution retries and state memoization without requiring complex boilerplate.20
The architecture specifically utilizes the human-in-the-loop pattern. The Workflow script (extending WorkflowEntrypoint) initiates by receiving a specific budget_item_id. To prevent runaway compute costs, it immediately pauses execution using the step.waitForEvent() API.13 For example, the script executes: const waitForApproval = await step.waitForEvent('Wait for AI Image tagging approval', { type: 'approval-for-research', timeout: '5 minute' });.13 The Workflow remains suspended in a zero-compute state until the user approves the action via the React UI. Upon approval, the frontend dispatches a payload ({ approved: true }) to the Workflow endpoint, which resolves the promise.13 The Workflow then resumes, executing sequential step.do() blocks to call search APIs, parse the DOM of vendor sites, chunk data into Workers AI for synthesis, and finally write the resulting ai_summary_output back to the D1 database.
4.2 Durable Objects & State (Chat Memory)
The integration of the assistant-ui chat interface requires highly stateful, low-latency communication to maintain conversational continuity. This requirement is fulfilled utilizing Cloudflare Durable Objects coupled directly with the @cloudflare/ai-chat package.28 Durable Objects provide globally unique, addressable instances that bind compute to localized persistent storage.30
The implementation defines a Durable Object class that extends AIChatAgent.29 A unique instance is instantiated per user session. This object maintains the entire conversational memory directly within its embedded, zero-latency SQLite database.31 This architecture ensures that if a user on a mobile device experiences a network drop, the WebSocket connection can immediately resume upon reconnection, seamlessly recovering the chat state without querying a central database.28 Furthermore, the system leverages WebSocket hibernation; when the user is idle, the Durable Object shuts down to conserve compute costs while maintaining the active connection.32 On the client side, the React application utilizes the useAgentChat hook provided by @cloudflare/ai-chat/react. This hook effortlessly wraps the WebSocket and exposes the messages array, sendMessage function, and streaming status directly to the assistant-ui runtime, completely abstracting the complex WebSocket lifecycle management.3
4.3 Queues (PDF Ingestion & Bulk Syncing)
Cloudflare Queues are deployed to manage unpredictable workload spikes and decouple heavy processing from user-facing API responses.
* PDF Ingestion Pipeline: When a user uploads a dense, 50-page contractor bid PDF, the receiving Worker does not attempt to parse it inline. Instead, it immediately returns an HTTP 202 Accepted response to the client and drops the binary payload (or an R2 reference key) into an ingestion-queue. A consumer Worker pulls these messages in manageable batches, runs OCR processes, and routes the extracted text through Workers AI to map the line items before writing the results to D1.
* Google Sheets Bulk Sync: To strictly adhere to Google Sheets API rate limits and avoid 429 Too Many Requests errors, all successful D1 mutations dispatch a lightweight message to a sheets-sync-queue. A secondary consumer worker batches these deltas every 10 to 30 seconds, constructing a single, massive spreadsheets.batchUpdate request. When retrieving document states, the API utilizes the includeTabsContent parameter set to true via the documents.get method to ensure all hierarchical sheets are analyzed.26
4.4 D1 SQLite (Relational Logic & Auditing)
Cloudflare D1 serves as the serverless relational database powering the core deterministic logic of the application. It handles the rigorous, standard SQL mathematics required for rolling up line items, tracking variances, and maintaining the revision audit log. The schema heavily utilizes foreign key constraints to maintain the absolute integrity of the MasterFormat mapping hierarchy. Because the bi-directional sync architecture requires frequent, high-speed read operations to compare inbound Google Sheets timestamps against the Sync_Revision_Log, the database configuration is tuned utilizing the PRAGMA cache_size directive, expanding the maximum number of database disk pages held in memory to optimize read latency.35

6. Open Questions & Future Iterations
To ensure seamless engineering execution and mitigate downstream architectural refactoring, the following critical areas require clarification from the Product and Engineering leadership during the initial Sprint Planning phase:
1. Google Sheets Rate Limit Tuning: While the implementation of the batchUpdate payload effectively mitigates absolute write limits 26, the exact interval at which the Cloudflare Queue flushes data to Google Sheets must be defined. Is a near-real-time flush (every 5 to 10 seconds) strictly necessary for user confidence, or is a 60-second debounced batch interval acceptable to further reduce API load and compute costs?
2. Durable Object Hibernation UX: To heavily optimize serverless costs, the architecture relies on WebSocket hibernation for idle chat sessions.32 How should the React UI handle the visual state (e.g., loading spinners, disabled inputs) during the brief, predictable latency incurred when a Durable Object wakes up from hibernation upon a user sending a new message after an extended period of inactivity?
3. Authentication & Multi-Tenant Isolation: Assuming the deployment utilizes Cloudflare Access or a standard JWT implementation for identity management, how will Row-Level Security (RLS) be strictly enforced at the D1 SQLite query level? It is imperative to ensure that users absolutely cannot access other homeowners' highly sensitive financial data or sync logs through manipulated API requests.
4. Assistant-UI Thread Management: The assistant-ui documentation explicitly states that multi-thread support requires a custom thread list wired around the useAISDKRuntime component.3 Will the initial v1 release support multiple distinct chat threads (e.g., one isolated thread for Kitchen negotiations, another for Bathroom sourcing), or will it utilize a single, global project assistant thread to minimize initial development complexity?
